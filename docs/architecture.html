The system boundary
is the product.

An agent can reason well and still corrupt the next system. The reliability layer belongs where memory, retrieval, evaluations, tools, or workflow state cross an authority boundary—not in another prompt telling the model to be careful.

Four invariants

Reasoning may be probabilistic. Promotion must be explicit.

  1. Exact public contract: expected keys and types, case and fact identities, evidence hashes, freshness, conflicts, and false external authority are checked before the synthetic artifact becomes eligible.
  2. Content and evidence-time binding: the public gate binds fact identifiers and hashes, rejects stale facts, and holds conflicting independent sources. Product-specific request, agent, dataset, prompt, or target-state identity belongs in the adapter contract when that boundary requires it.
  3. Bounded uncertainty: retries have a finite attempt budget and named terminal states. An unknown effect is not silently converted into success.
  4. Explicit authority: a review receipt is not a send, write, deployment, order, or payment permit. External action remains false until its real owner grants it.

Design rule: validate the exact artifact, own the lifecycle, record the decision, then hand off. Never infer effect authority from a plausible output.

The pipeline

One narrow path from untrusted bytes to a reviewable decision.

untrusted artifact
  → strict decoder and exact keyset
  → evidence admission and freshness/conflict checks
  → bounded lifecycle with request fingerprint
  → owned decision journal and replay check
  → review-required handoff

The checked-in operating core composes four small owners instead of hiding the boundary in a framework:

Evidence gate
draft | escalate | hold, with a named reason
Polling contract
fingerprint reuse, finite attempts, backoff, timeout, unknown-id terminal state
EGOH journal
scenario + evidence digest + decision replay, with conflicting records refused
Operating core
only admitted evidence enters the lifecycle; complete work still requires a separately accepted EGOH observation before review

Uncertain effects

A timeout is a state, not permission to try blindly again.

When an external system may have accepted a request before the connection failed, an automatic retry can duplicate the effect. The public polling contract reuses a previously submitted operation for the same fingerprint and ends in explicit terminal states when completion cannot be established. Payload-equivalence enforcement belongs in a real adapter built around that contract; the synthetic polling reference does not claim it.

  • Repeated fingerprint: reuse the polling operation already owned by that fingerprint.
  • EGOH replay: reuse only the same scenario, evidence digest, and decision; reject a conflicting record.
  • Polling timeout or unknown operation identity: stop in the named terminal state; the composed core does not create a handoff.
  • Complete lifecycle: continue only if a separate EGOH observation is accepted; then produce a review-required handoff, never autonomous external authority.

Hostile proof

The refusal paths are part of the deliverable.

  • Missing: a required fact, score, trace, or source never arrived.
  • Stale: evidence is structurally correct but outside the accepted epoch.
  • Conflicting: independent fresh sources disagree.
  • Digest mismatch: EGOH receives evidence whose declared digest does not match its canonical bytes. A client adapter can extend this into descriptor-bound source and target revalidation where required.
  • Duplicate: a replay tries to create a second owner or effect.
  • Unknown outcome: transport ended before effect identity was proven.
