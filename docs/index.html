У вас є AI або data артефакт, якому не можна повністю довіряти. За один фіксований спринт я збираю малий adapter: він перевіряє передачу, відмовляє за missing, stale, malformed, substituted або contradictory evidence і повертає письмовий decision trace для людського review.

Конкретний обмін

Що ви даєте. Що означає «готово».

Ви даєте: один sanitized sample artifact, очікувану schema, описи source і target interface та один дорогий failure, який adapter має відмовити. Для sprint не потрібні credentials чи production access.

Acceptance: погоджений valid fixture проходить; missing, malformed, stale, substituted і contradictory fixtures fail closed; decision trace називає reason; proof command проходить; межі й невирішені blockers записані.

Handoff: включено один review round. Production deployment, certification, SLA, support, доступ до client-system і automatic activation не входять. Repository та licensing погоджуються до початку роботи.

Серйозна система починається вузько

Одна доведена передача до будь-якого більшого control layer.

Єдиний крок, який можна купити зараз, — фіксований sprint вище. Наступні шари розглядаються лише коли його письмовий evidence називає реальну межу, яку варто нести далі.

  1. 01 · можна купити зараз

    Одна fail-closed передача

    Один bounded adapter, hostile acceptance proof, decision trace і known-limits handoff у фіксованому sprint.

  2. 02 · після Stage 1 evidence

    Harden agent/runtime control plane

    Пізніший письмовий scope може посилити межу, яку відкрив sprint. Це не включено, не оцінено і не обіцяно першим sprint.

  3. 03 · після evidence

    Operator system roadmap

    Пізніша roadmap може назвати proof gaps, межі owner та наступні operator decisions. Вона не authorizes implementation.

Публічний runnable evidence

Перевірте метод до купівлі sprint.

Repository містить dependency-free reference для evidence gates, bounded asynchronous polling, operator handoff та explicit terminal failure states. Одна команда запускає demo tests; це не safety guarantee для майбутнього client adapter.

python3 run_proof.py

Що це доводить

  • Missing evidence не стає success.
  • Retries і polling мають hard bounds.
  • Duplicate effects та ambiguous outcomes утримуються.
  • Human approval лишається explicit.

Чого це не доводить

Production deployment, client results, security certification або access до ваших systems.

Failure trace explorer

Подивіться, чому unsafe handoff зупиняється.

Оберіть checked-in synthetic case. Trace показує named reason, buyer-facing triage outcome і межу non-authorization.

Хороший перший use

Принесіть передачу, якій ваша команда не довіряє.

Наприклад: agent result входить у internal tool, model artifact переходить у runtime, async job може брехати status або data receipt мусить пережити malformed і racing inputs.

Якщо корисний proof не можна завершити в погодженій межі, ви отримаєте чесний hold report з точним blocker-ом і reusable artifacts.
