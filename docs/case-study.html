The failure

“Looks valid” is not an acceptance rule.

Consider an AI receptionist that emits a booking outcome, a document pipeline that emits extracted fields, or an agent that proposes a CRM update. The output may be well-formed and still be ineligible.

  • It belongs to an older request or source generation.
  • It was substituted after an earlier validation.
  • Required evidence is missing while the payload still looks plausible.
  • Two fresh sources contradict each other.
  • The target state already changed, so replay would duplicate an effect.

Core rule: the adapter does not ask whether the output looks useful. It asks whether the exact artifact is eligible to cross this exact boundary now.

The bounded contract

One source. One target. Named refusal reasons.

A useful first reliability layer stays deliberately small. It binds the source artifact, the target interface, the decision owner, the expensive false promotion, and the evidence required for acceptance.

Minimum inputs

  1. One sanitized source artifact and its expected schema.
  2. Source and target interface descriptions.
  3. One costly outcome the handoff must refuse.
  4. One valid fixture and the hostile fixtures that must stop.

The hostile proof

Test the refusal path, not only the happy path.

The public repository includes dependency-free references for evidence decisions, bounded polling, replay handling, and a synthetic operator handoff. The important tests are the ones that try to make an unsafe artifact look acceptable.

  • Missing: a required evidence source is absent.
  • Stale: the artifact is structurally valid but outside its allowed epoch.
  • Substituted: the path or bytes change after an earlier check.
  • Contradictory: individually valid sources disagree.
  • Replay: the same operation arrives again after an uncertain outcome.
